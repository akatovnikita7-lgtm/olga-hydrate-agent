# Сборка агента для обхода МБСНУ

Объединены feat/agent-client, feat/olga-adapter и feat/results-analysis.
Агент принимает текстовый запрос, проверяет готовый сценарий, показывает план,
после «да» запускает отдельную копию модели, ждёт завершения и строит графики/CSV.
Поддержан один сценарий: 96 ч, переключение на 48 ч за 60 с.
Произвольные изменения схемы, подбор оптимального режима и расчёт гидратов не реализованы.
Набор графиков фиксирован: расходы GT и давления PT в контрольных точках манифеста.

## Первый запуск на твоём Windows

1. Распакуй архив, например в `C:\OLGA_Agent`. Открой папку `well-agent`.
2. Установи Python 3.12, если его нет. Дважды нажми `setup.cmd`.
3. Собери **копии** актуальных `case1_obhod.genkey` и `Novosam_T1_HeaderFix.tab`
   в одну папку, например `C:\OLGA_Model\obhod`. В GENKEY ссылка на PVT должна быть
   относительной: `./Novosam_T1_HeaderFix.tab`. Если `.opi` есть, его можно положить рядом.
   `.opp` для пакетного запуска не нужен. Исходные файлы не удаляй.
4. Открой созданный `.env` в Блокноте. Заполни:
   - `LLM_API_KEY` — твой ключ Groq, локально, без отправки в чат;
   - `OLGA_CASE_KIT_DIR=C:/OLGA_Model/obhod`;
   - `OLGA_LAUNCHER` — полный путь к проверенному исполняемому файлу решателя OLGA;
   - `OLGA_LAUNCHER_ARGS` — JSON-список аргументов пакетного запуска.
     Пример формы: `["{input}"]`. **Это пример, не подтверждённая команда для твоей установки.**
     Нужны настоящий exe и аргументы из рабочего batch-запуска на твоём ноутбуке.
     GUI-приложение OLGA и решатель могут быть разными exe.
5. Дважды нажми `check_olga.cmd`. Он проверит комплект и подготовит план, без расчёта.
   Готовность плана не подтверждает наличие лицензии или правильность команды запуска.
6. В PowerShell в этой папке выполни `.\.venv\Scripts\python.exe -m scripts.check_llm`.
7. Дважды нажми `start_agent.cmd`. Введи:
   `Запусти обход МБСНУ на 96 часов с переключением на 48 часах за 60 секунд.`
8. Проверь показанный план и введи `да`. Оставь окно открытым до конца расчёта.

Если не знаешь путь к решателю/аргументы, пришли список файлов каталога установки OLGA
или команду успешного batch-запуска. Не подставляй случайный exe.

## Где результаты

Каждый запуск работает в новой папке `well-agent/runs/run_.../model`.
В ней остаются `.out`, `.tpl`, а в подпапке `analysis`:

- `results.xlsx` — книга Excel с листами для сравнения, объёмов, каналов и временных рядов;
- `overview.png` — расходы и давления за весь расчёт;
- `transition.png` — приближение переключения;
- `series.csv` — все исходные численные ряды (время в секундах, исходные единицы);
- `channels.csv` — точные ID, ветви, SECTION/BOUNDARY, PIPE, NR, единицы;
- `volumes.csv` — объёмы по периодам, если есть пары ACCLIQ/QLT;
- `comparison.csv` — сопоставимые показатели автоматического и ручного прогона.
  Эталон поставляется в `results/manual_case1_obhod/metrics.json`.
  Сравнение сверяет расписание и каналы PT/QLT, но версия модели ручного прогона
  не подтверждена отпечатком. Инженерные допуски не заданы.
- `summary.json` — минимум/максимум, начальные/конечные значения и предупреждения.

Для уже завершённого прогона запусти `export_excel.cmd`. Он создаст книгу из CSV
последнего прогона. Для другого прогона перетащи папку `analysis` на этот файл.

Клиентский журнал и итоговый ответ — в `logs`. Завершение OLGA и инженерная
пригодность результата — разные вещи: без допустимых давлений оценка NOT_ASSESSED.
Агент не ускоряет решатель OLGA: новый расчёт занимает обычное время.
Ctrl+C/закрытие окна может остановить дочерний расчёт, особенно на Windows.
Порог ожидания 6 часов даёт предупреждение, но не закрывает работающий клиент.

## Показ на защите без повторного расчёта

Можно разобрать уже готовый `.tpl`:

```powershell
.\.venv\Scripts\python.exe -m scripts.analyze_export "C:\OLGA_Model\obhod\case1_obhod.tpl" --output "C:\OLGA_Demo\export1"
```

Используй новую папку вывода. Это анализ архивного расчёта, не новый запуск OLGA.
Показ результата из архива нужно так и обозначить.

## Проверка кода без OLGA и ключа LLM

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

Интеграционные тесты запускают настоящий MCP-сервер и **синтетический** процесс fake_olga.
Разбор запроса LLM в этих тестах подменён фиксированным ответом. Они проверяют связность
программы, а не физику, лицензию OLGA или доступность Groq.
Тестовый CLI `python -m scripts.demo --test-mcp` также выдаёт синтетические данные.
Без `--execute` обычный CLI только проверяет запрос, не запускает расчёт.

## Границы проверки этой сборки

Сборка проверяется в Linux без установленной OLGA. Для окончательного подтверждения
на твоём ноутбуке нужны: успешная проверка LLM, правильная команда batch-запуска,
завершение одного реального запуска через агент и сравнение его результатов с ручным.
