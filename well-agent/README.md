## OLGA: анализ гидратообразования и перепуска в байпас



## Задача

Разработка агента для анализа условий гидратообразования по результатам нестационарных расчётов OLGA. Агент определяет участки и режимы риска и формирует обоснованные рекомендации по перепуску в байпас, подаче ингибитора или изменению режима. Проверка включает сценарии останова и пуска.

Пример запроса:

> Проанализируй сценарий пуска, найди участки с риском гидратообразования и предложи действие с указанием условий его применения.

## Архитектура

```text
запрос инженера
      ↓
agent.py → src/agent → MCP-клиент
                         ↓
                mcp_server/server.py
                         ↓
              адаптер инженерного ПО
                         ↓
                  симулятор и модель
```

Агент и MCP-сервер являются отдельными компонентами. Код агента не импортирует
OpenServer, COM или SDK симулятора. Вендорские зависимости находятся только в
`mcp_server/`.

## Структура

```text
agent.py                 точка входа run(request, ctx) -> AgentResult
src/agent/               цикл, схемы, промпты и MCP-клиент
mcp_server/              локальный сервер и адаптер выбранного ПО
tests/                   тесты контракта и предметных сценариев
notebooks/demo.ipynb     демонстрация основного сценария
docs/                    схема, ограничения и материалы защиты
project.yaml             метаданные проекта
```

## Быстрый старт

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m pytest
```

Локальный MCP-сервер запускается отдельным процессом:

```powershell
python -m mcp_server.server
```

## Что уже есть в шаблоне

- контракт `run(request, ctx) -> AgentResult`;
- Pydantic-схемы результата, чисел и журнала;
- порт `ToolGateway` и заготовка MCP-клиента;
- фабрика MCP-сервера с двумя демонстрационными инструментами;
- адаптер симулятора, который намеренно не возвращает выдуманные результаты;
- минимальные тесты структуры и контракта.

## Что реализует команда

- структурный разбор запроса через LLM;
- инструменты для выбранной инженерной задачи;
- настоящий вызов симулятора в `mcp_server/simulator/client.py`;
- проверку единиц, диапазонов и полноты данных;
- обработку ошибок симулятора и лицензии;
- заполнение `values`, `sources` и `trace`;
- тестовые сценарии с эталонами и ожидаемыми отказами;
- демонстрационный ноутбук и документацию.

## Ограничения шаблона

Каркас не подключён к промышленному ПО и не выполняет расчёты. Метод
`SimulatorClient.run_case` завершает работу явной ошибкой, пока команда не добавит
адаптер выбранного симулятора.

Для запуска из Colab нужен доступный по сети MCP endpoint. `localhost` в Colab не
указывает на компьютер, где установлен симулятор.
